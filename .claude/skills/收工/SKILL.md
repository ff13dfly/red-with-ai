# /收工 —— 当天收工流程

用户输入 `/收工` 时执行。这是 `red`（red-with-ai）小红书项目每天的固定收尾动作：**把今天的问答 log 补全 → 只提交 log → 推送备份**。

节奏依据：本项目记录与提交分离——平时只往 log 里写、不提交；log 在收工时一次性提交；README/草稿/配置等其他改动只在用户单独指令时才提交。

## 步骤

1. **确定日期与时间**
   - 运行 `date "+%Y-%m-%d"` 得到今天日期（记作 TODAY），对应日志 `log/TODAY.md`。
   - 运行 `date "+%H:%M"` 取当前时间备用。

2. **补全今天的 log（`log/<TODAY>.md`）**
   - 文件不存在就按既有格式新建（标题、说明、`协作工具/模型` 行、`---` 分节）。
   - 回顾本次对话里**还没记进 log 的问答**，按既有格式补上。每条：
     - `## N. 小标题`
     - `> 时间 HH:MM · 模型 <当前实际所用模型>`
     - `**问：**`（尽量保留原话）
     - `**答（要点）：**`（整理成可读要点，保留实质内容）
   - 时间用 `date` **实时取**，不要凭记忆估；模型写当前实际所用模型。
   - **不倒填历史**：历史条目里缺失的时间/模型一律不补假数据。
   - 确认结尾有「素材待挖掘」内容点子；若当天遇到 prompt 注入等安全事件，记进「安全提醒」。

3. **只提交 log**
   - `git add log/`（**只加 log 目录，不要 add README / 草稿 / 配置等其他改动**）。
   - 若 `git status` 显示 log 无改动，告知「今天 log 没有新内容」并跳过提交与推送。
   - 提交信息用 here-doc，正文 `log: <TODAY> 当日问答记录`，末尾加：
     `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>`

4. **推送**
   - `git push`（`origin`/upstream 已设好）。
   - 失败就把报错**原样**给用户，不要尝试绕过或改配置。

5. **汇报**（一两句）
   - 提交了哪个 log 文件、commit 短哈希、推送是否成功。
   - 若还有其他未提交改动，提醒「它们仍留着，等你单独指令再提」。

## 注意
- 这是**手动收尾**动作，默认不自动触发，只在用户 `/收工` 时执行。
- 严格遵守「只提交 log」：不要顺手把其他文件一起 commit。
