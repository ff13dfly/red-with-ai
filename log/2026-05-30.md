## 7. 用 IndexedDB 做笔记数据追踪工具

**问：** 「发布后回填」不是做数据分析用的吗？为什么不在 tools 里创建个工具？用 IndexedDB，隐私和功能规模都能控制住，对吧？

## 8. 能自动拉取笔记数据吗？

**问：** 有办法自动统计每个笔记的这些数据吗？应该也是一个 URL，对吧？

**答：** 在浏览器 HTML 工具里做不到，根本上有三堵墙：①小红书没有公开 API；②CORS + 登录态拦截，fetch 直接被拒；③React SPA + 反爬签名，数据在 JS 执行后才渲染，直接抓 HTML 拿不到数值。理论上能做到的路径（浏览器插件读 DOM / Python 逆向非官方 API / 专业号后台导出 Excel）都有较高维护成本或违反服务条款。结论：对当前规模（每周几篇），手动填 4 个数字用不了 1 分钟，不值得为此引入复杂自动化。合理的小改进是在 post-tracker 录入表单里给链接加「打开」按钮，看完数字填回来，动作流畅即可。

## 13. cover-overlay 加自动缓存

**问：** 需要对当前操作缓存，上传的图、写好的文字存 localStorage，刷新后还能恢复。

**答：** 图层（小 JSON）存 localStorage，背景图（可达 5MB+）存 IndexedDB。cover-overlay.html 升到 v1.3：①`loadBlob` 改用 FileReader 转 dataURL，确保上传图可以存入 IDB；②`loadUrl(url, persist=true)` 加载成功后异步写 IDB；③`render()` 末尾调 `saveLayers()` 写 localStorage；④页面 load 后调 `restoreState()` 恢复图层和背景图；⑤加「清空工作区」按钮（confirm 确认后清除 localStorage + IDB + canvas）；⑥侧边栏底部加「✓ 已缓存」指示器，1.8s 后自动淡出。
